## 2. What the Python side lacks

Against the C++ example layer: nothing (same features; the package also takes a user's own search).

Against the engine (C++ only, not reachable from Python):

| kind | missing from Python |
|---|---|
| algorithms | `DiversificationSearch`, `ImprovingTabuSearch` (and `diversification_tenure`); building an algorithm and passing it in (`create_algorithm`, `solve(Algorithm*)`) |
| bidirectional search | a clock resource of another type than the cost |
| label containers | containers other than the default list and numerical buckets |
| resources | unsigned and `size_t` types, `size_t` sets and bitsets (the C++ VRP example uses a bitset); graph combinations beyond those bound |
| resource functions | `ReachableFeasibilityFunction`, trivial extension and dominance, per-node capacity and min-max bounds, functions written in Python, `add_coherent_resource`; `add_cost_resource` real only |
| graph | `sort_nodes_by_connectivity`, the full model report (Python gets the problem list) |
| open PRs | everything they add, until merged and bound |

In the benchmark and the examples: no ng size (the `graph` block is empty; the ng runs so far were by hand), no ng in
the Python VRP example; bucket parameters in a stage not checked. In the package, against the field (phase 2): no
Lagrangian bound, gap stop, column pool, column management, stabilization, pricing budget, pricer schedule, parallel
pricers; per-iteration data limited to objective and column counts.

## 3. The all-features test

Small instances (C101_25, R201_25, RC201_25), through the benchmark, every layer and master that has the feature:

| area | runs |
|---|---|
| graph | ng size 0 and 8 (needs the option); elementary routes on the smallest |
| exact pricing | simple, pushing, pulling, A\*, bidirectional; simple backward and bidirectional; half-way point, join after an early stop; preprocessing on and off; buckets |
| heuristic stages | greedy (capped) then exact; tabu then exact; a stage `timeout_s`; `max_solutions` |
| starts | artificial, single-customer, none (feasible model) |
| several pricers | two vehicle types, one graph and convexity row each (`T-1.9`) |
| loop | iteration and time limits (their statuses); relative tolerances; threads; hooks (iteration, convergence changing a pricer); Ctrl-C |
| after the loop | the integer solve; `solution.json` checked against the instance |

Checks: per instance and ng size, the same LP for every exact configuration, layer and master; LP without ng ≤ LP
with ng ≤ elementary LP; heuristic stages end with an exact proof; limits end with their status; the integer solution
feasible and ≥ the LP. A seconds-long subset for CI, the rest by hand (`T-1.29`).
